# Documentation Playbook (What Companies Usually Maintain)

This is a practical list of documents to run this as a business, not just a code project.

## 1) Core company docs (foundational)

Create these first:

1. Vision + Positioning (1 page)
   - Who this is for
   - What problem you solve
   - Why your approach is different

2. Product Requirements Doc (PRD)
   - Feature goals
   - User stories
   - Success metrics
   - Non-goals

3. Architecture Guide
   - System components
   - Data flow
   - Dependencies
   - Failure points

4. Go-To-Market (GTM) Plan
   - Acquisition channels
   - Pricing
   - Launch plan
   - Growth hypotheses

5. KPI Dashboard Spec
   - Metrics definitions
   - Data source
   - Weekly targets

## 2) Product docs (build + improve)

1. Feature specs
2. User journey maps
3. Experiment log (A/B tests)
4. Release notes / changelog
5. UX research notes

## 3) Engineering docs (quality + continuity)

1. API contract docs
2. Runbooks (incident handling)
3. Environment/config docs
4. Deployment checklist
5. Security checklist
6. Test strategy doc

## 4) Business ops docs

1. Pricing model doc
2. Unit economics sheet
3. Customer persona cards
4. Sales deck + FAQ
5. Partnership playbook

## 6) Recommended documentation cadence

### Weekly
1. Metrics review update
2. Experiment log update
3. Bugs/issues summary

### Monthly
1. Roadmap review
2. GTM and channel review
3. Product quality trend review

### Quarterly
1. Strategy reset
2. Pricing and unit economics review
3. Competitive landscape update

## 7) Templates you can copy quickly

## Vision template

1. Target user:
2. Core pain:
3. Product promise:
4. Why now:
5. Why us:

## PRD template

1. Problem statement
2. Goal
3. Scope (in/out)
4. User stories
5. UX notes
6. Metrics
7. Risks + mitigations
8. Rollout plan

## KPI template

1. Metric name
2. Formula
3. Source
4. Owner
5. Target
6. Review frequency

## Incident template

1. What failed
2. User impact
3. Root cause
4. Fix applied
5. Prevention action
6. Owner + deadline

## 8) Recommended current priority for your app

Given your stage, start in this order:

1. `VISION.md`
2. `PRD_v1.md`
3. `KPI_DEFINITIONS.md`
4. `RUNBOOK.md`
5. `GTM_PLAN.md`

This gives clarity for both product build and business growth.

## 9) Who should own each document (even if team is small)

1. Founder/CEO: Vision, GTM, Pricing
2. Product owner: PRD, Roadmap, Experiments
3. Engineer: Architecture, Runbooks, Deploy docs
4. Shared: KPI definitions and weekly review
